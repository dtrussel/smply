# cppcheck cannot reliably parse Catch2-based test translation units. It runs
# without the project's include paths, so TEST_CASE, SECTION and REQUIRE are
# unknown macros, and it explores preprocessor configurations that no build
# uses -- it reports "Too many #ifdef configurations" on the same run. On
# tests/unit/test_os_group.cpp that combination produces a syntaxError at the
# first TEST_CASE; supplying the include paths and a smaller check set makes it
# vanish, which is what identifies it as a parser artefact rather than a defect.
# ---
# Suppressed only for tests/, and only this id. A real syntax error in a test is
# caught immediately by GCC, Clang and MSVC, all three of which compile these
# files, so cppcheck's parser adds nothing here -- whereas letting it block CI
# on a construct it cannot parse makes the gate worse than useless. Nothing is
# suppressed for include/ or src/.
syntaxError:tests/*
